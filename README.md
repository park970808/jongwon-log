# 종원 공동 활동일지 — Firestore 시험판

알한글/rhwp의 실제 웹 편집기에 Yjs와 Firestore 전송 계층을 연결했습니다. 칸별 잠금 없이 같은 셀의 글을 함께 입력하며, 본문·표·서식을 포함한 HWPX 문서 전체를 다룹니다. **현재는 팀 시험용 구현입니다. 기존 운영 화면을 즉시 대체하기 전 실제 팀 문서로 검증해야 합니다.**

## 실행

Node.js 22.12 이상 권장. 저장소 루트에서:

```sh
npm ci
npm run dev
```

표시된 로컬 주소를 열고 **기기 내 체험**을 누릅니다. 링크를 같은 브라우저의 다른 탭에 붙여 넣으면 동시 편집을 확인할 수 있습니다. 이 체험은 로컬 브라우저끼리만 연결되며 Firestore에 저장하지 않습니다.

팀원들과 다른 컴퓨터에서 사용하려면 [배포 안내](DEPLOYMENT.md)의 Firestore 규칙·팀 권한 설정 후 **Firestore 문서 열기**를 사용합니다.

```sh
npm run build
npm run preview
```

배포 대상은 생성된 **dist 폴더 전체**입니다. `index.html`은 진입점이지만 JavaScript, WASM, 폰트가 필요하므로 HTML 한 파일만 업로드하거나 더블클릭해서 실행할 수 없습니다. GitHub Pages의 프로젝트 하위 경로를 지원하도록 상대 경로로 빌드합니다.

## 사용 흐름

1. 팀·이름·주차·문서 ID를 입력하고 Firestore 문서를 엽니다.
2. 처음 만드는 문서는 기본 활동일지 양식을 사용하거나 HWPX를 가져옵니다.
3. **링크 복사**로 동일한 문서 주소를 공유합니다. 팀 편집 권한을 받은 사용자가 같은 문서를 엽니다.
4. 같은 셀을 여러 사람이 입력할 수 있습니다. 글자 서식과 표 행 추가도 변경 기록으로 공유됩니다.
5. **Firestore에 저장됨**을 확인하거나 **HWPX 내려받기**로 파일을 받습니다.

기존 화면과 양식은 `legacy/`에 보존했습니다. 기존 화면에서 **한글 파일 내보내기** → 새 공동 문서에서 HWPX 가져오기로 이전합니다. 기존 Firestore 문서를 자동 변경하거나 삭제하지 않습니다. 옛 화면과 새 문서는 이전 후 서로 다른 문서이므로 양쪽 수정이 자동 교환되지는 않습니다.

## 구조

```text
알한글 웹 편집기 (studio.html / WASM)
          ↕ 로컬 변경 분석 · 원격 변경 반영
HWPX 문서 구조 ↔ Yjs 문서 (텍스트·서식·표·첨부 개체)
          ↕ 변경 묶음 / IndexedDB 복구본
Firestore 업데이트 로그 ↔ 다른 팀원의 브라우저
          ↓ 선택 배포
일일 체크포인트 함수 (원본 로그는 유지)
```

- `src/document-model.js`: HWPX XML ↔ 공유 문서, 텍스트 병합, 스타일/이미지 참조 정규화.
- `src/editor-binding.js`: 실제 편집기와 공유 문서 연결, 조합 입력 대기, 개인 실행 취소.
- `src/sync-provider.js`: 업데이트 압축·해시 검증·영속 outbox·재시도.
- `src/firestore-backend.js`: 추가 전용 로그, 128 KiB 청크, 초기 복원, 접속자 커서.
- `functions/`: 선택적 체크포인트. 100개 이상 업데이트를 묶고 이후 늦은 수정도 복원합니다.
- `vendor/rhwp/`: MIT 라이선스 rhwp v0.8.6 편집기와 제공된 알한글 DMG의 호환 WASM.

HTML 전체를 Firestore의 한 필드에 덮어쓰지 않습니다. Yjs 변경은 중복·역순 수신에도 병합되며, HWPX 구조로 다시 내보내 편집기에 반영합니다. 전송은 Firestore만 사용하며 별도의 협업 WebSocket 서버는 없습니다.

## 검증

```sh
npm test
```

실제 Chrome 편집기 검사와 Firebase 에뮬레이터 검사는 [TESTING.md](TESTING.md)를 참고하세요. 같은 셀의 동시 한글 입력, 상대방 글을 보존하는 실행 취소, 오프라인 재접속, 새로고침 복원, 글자 굵게, 한글 조합 이벤트, 표 행 추가, 권한 규칙, 체크포인트 경계를 검증했습니다.

## 현재 범위와 제한

- 기본 활동일지 양식의 Chrome 데스크톱 동시 편집을 검증했습니다. 임의의 모든 한글 문서·기능·브라우저에 대한 호환성을 보장하는 버전은 아닙니다.
- 같은 표의 복잡한 동시 구조 변경(셀 병합·삭제·이동), 머리말/각주 커서, 선택 영역 보존, 대용량 이미지와 새 글꼴 동시 추가는 추가 검증이 필요합니다. 표 행 추가 1건의 전파는 검증했지만 모든 구조 충돌 해결을 의미하지 않습니다.
- 네이티브 내보내기의 문단 ID가 재생성되므로 내용 기반으로 문서 노드를 대응합니다. 문단 이동/삭제와 동시 입력처럼 모호한 경우는 안정 ID를 직접 제공하는 엔진 통합이 후속 과제입니다.
- 원격 반영은 문서 재렌더링 방식입니다. 반영 중 발생한 일반 텍스트·한글 조합·키 이벤트는 보관 후 재생합니다. 큰 문서의 지연, 복합 붙여넣기와 선택 영역 안정성은 추가 검증이 필요합니다. 반영 중 붙여넣기는 일반 텍스트로 보관합니다.
- 한 번의 압축 변경 묶음/체크포인트는 최대 4 MiB, 해제 후 최대 96 MiB입니다. 큰 사진 문서는 제한될 수 있습니다. Firebase Storage를 통한 별도 이미지 저장은 아직 구현하지 않았습니다.
- 체크포인트가 있어도 원본 로그를 삭제하지 않습니다. 읽기/쓰기·저장량 비용을 관찰해야 합니다. 접속자 위치도 Firestore 쓰기를 사용합니다.
- 초기 인증은 익명 Firebase UID + 관리자 등록 방식입니다. 브라우저 데이터 삭제/기기 변경 시 UID가 달라져 재등록해야 합니다. 영구 계정 로그인과 초대 UI는 후속 작업입니다.
- 오류 발생 시 편집을 멈추고 **복구 데이터 받기**로 Yjs 원본과 화면의 HWPX를 보존합니다. Yjs 복구본 자동 업로드 UI는 아직 없습니다.
